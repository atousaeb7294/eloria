## محتویات بسته

پوشهٔ `eloria` کد کامل پروژه و تصاویر اصلی آن است. پوشهٔ `update` پچ همین اصلاح را روی نسخهٔ موجود اعمال می‌کند. فایل‌های خصوصی `.env`، تاریخچهٔ `.git`، وابستگی‌های `node_modules`، خروجی `.next` و دیتابیس در ZIP قرار ندارند. مدل حذف پس‌زمینه مانند نسخهٔ فعلی پروژه هنگام build دریافت و checksum آن بررسی می‌شود.

## تغییرات

- عکس معمولی تمام دهانهٔ دریچه را پر می‌کند؛ تصویر شفاف محصول تنظیم جداگانه دارد.
- ارتفاع کامل طاق و گل‌های پایین حفظ شده و فاصلهٔ منفیِ عامل بریدگی حذف شده است. سایه و انتهای پایه با زمینه ترکیب می‌شوند.
- در موبایل، طاق‌ها از قاب مستطیلی جداکننده خارج شده‌اند؛ دو لنگه حول لولا حرکت می‌کنند.
- دکمهٔ باز/بسته کردن دیده می‌شود؛ لمس دوم، کلیک و Escape کار می‌کنند. کلیک پس از hover عکس را ناخواسته نمی‌بندد.
- در خطای تصویر شفاف، عکس همان محصول با حالت پوشش صحیح نمایش داده می‌شود.
- لایهٔ انتظار ورود سینمایی پیش از آماده شدن جاوااسکریپت روی کل صفحه نمی‌ماند. مسیرهای رد کردن و بازیابی پخش حفظ شده‌اند.
- قانون opacity که نسخهٔ سبک و باکیفیت تصویر اصلی را هم‌زمان نشان می‌داد اصلاح شده است.
- عنوان‌های فارسی با طول متن رشد می‌کنند؛ فضای قلم نستعلیق و عرض صفحهٔ کوچک اصلاح شده است.

## نصب روی C:\eloria

برنامهٔ در حال اجرای همین پروژه را با Ctrl+C متوقف کنید. Git و Node.js 22 یا 24 لازم‌اند. فقط اگر نصب نیستند، دستور مربوط به نرم‌افزار ناموجود را اجرا کنید و سپس PowerShell را دوباره باز کنید:

```powershell
winget install --id Git.Git --exact
winget install --id OpenJS.NodeJS.LTS --exact
```

ZIP را در Downloads ذخیره و این دستورها را اجرا کنید:

```powershell
$zip = Join-Path $env:USERPROFILE 'Downloads\eloria-complete-repair-20261101.zip'
$bundle = 'C:\eloria-repair-20261101'
Expand-Archive -LiteralPath $zip -DestinationPath $bundle
powershell -NoProfile -ExecutionPolicy Bypass -File "$bundle\eloria\scripts\install-storefront-repair.ps1" -ProjectRoot 'C:\eloria' -UpdateDirectory "$bundle\update" -Build
```

اگر فایل جای دیگری است، `$zip` را عوض کنید. اگر قبلاً استخراج کرده‌اید، دستور Expand-Archive را تکرار نکنید. بسته را در پوشه‌ای جدا از پروژه استخراج کنید.

نصاب checksum و قابل‌اعمال بودن پچ را بررسی می‌کند. فایل‌های دارای تداخل را بازنویسی نمی‌کند. نسخهٔ قبل فایل‌های تغییرکرده را در `C:\eloria-update-backups` نگه می‌دارد؛ تغییرات نامرتبط و فایل‌های `.env` حفظ می‌شوند. در صورت نبودن مسیر پروژه، مخزن را clone می‌کند. مسیر موجود باید همان مخزن Git باشد.

سپس `npm ci`، تولید Prisma Client، بررسی TypeScript و تست‌های مرتبط اجرا می‌شوند. `-Build` یک build آزمایشی بدون دیتابیس می‌سازد؛ برای تست سریع‌تر می‌توانید این گزینه را حذف کنید.

**هیچ PostgreSQL محلی، migration، seed یا reset دیتابیس اجرا نمی‌شود.** آدرس آزمایشی فقط در حافظهٔ فرایند فرزند است و تنظیمات شما تغییر نمی‌کنند. در build آفلاین، پیام نبود دیتابیس برای محتوای پویا طبیعی است؛ پایان موفق با پیام `Storefront verification passed` مشخص می‌شود.

در صورت پیام تداخل، فایل‌ها را با کل پوشهٔ ZIP جایگزین نکنید؛ پچ باید با تغییرات جدید شما ادغام شود. نصب مجدد، پچ اعمال‌شده را تشخیص می‌دهد.

## انتقال به main

بعد از نصب موفق:

```powershell
Set-Location 'C:\eloria'
git diff --stat
powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\publish-storefront-repair.ps1' -ProjectRoot 'C:\eloria'
```

اسکریپت فقط فایل‌های `docs/STOREFRONT_REPAIR_FILES.txt` را stage می‌کند، شاخهٔ اصلاح می‌سازد، commit می‌کند، `origin/main` را می‌گیرد، اصلاحات را با `main` ادغام می‌کند و `git push origin main` اجرا می‌کند. force push و reset ندارد. هنگام خطا متوقف می‌شود. اگر GitHub ورود خواست، با حساب خودتان وارد شوید.

اگر نام/ایمیل commit تنظیم نیست، در همین مخزن با مشخصات خودتان اجرا کنید:

```powershell
git config user.name 'YOUR NAME'
git config user.email 'YOUR VERIFIED GITHUB EMAIL'
```

در این نوبت هیچ push یا deploy روی سایت زنده انجام نشده است؛ دستور بالا از حساب شما اجرا می‌شود.

## پارس‌پک

پس از push، در صورت اتصال استقرار خودکار به main، نتیجهٔ build/deploy را در پنل بررسی کنید. در غیر این صورت آخرین commit شاخهٔ main را با روش فعلی پروژه deploy کنید.

تنظیمات موجود DATABASE_URL، DIRECT_URL و رمزهای دیگر روی پارس‌پک باقی می‌مانند. این اصلاح schema دیتابیس را عوض نمی‌کند. **خروجی `.next` بررسی آفلاین ویندوز را روی سرور کپی نکنید**؛ سرور باید با تنظیمات واقعی خودش build شود.

اجرای محلی با دادهٔ واقعی تنها وقتی ممکن است که دیتابیس پارس‌پک اتصال بیرونی را مجاز کرده باشد. در آن صورت تنظیمات را در فایل خصوصی `.env.local` خودتان قرار دهید و `npm run dev` بزنید. نیازی به نصب دیتابیس روی ویندوز نیست. اگر آدرس دیتابیس داخلی پارس‌پک است، تست آفلاین و push قابل‌اجرا هستند اما اجرای محلی با دادهٔ واقعی ممکن نیست. فایل env را به Git اضافه نکنید.

## اعتبارسنجی

اجزای واقعی طاق و CSS پروژه در نمای دسکتاپ و عرض‌های ۳۹۰ و ۳۲۰ پیکسل بررسی شدند؛ تصویر محصول، پایه و گل‌ها، کنترل باز/بسته شدن و متن فارسی بازبینی شدند. رفتار لمس و خطای عکس با تست کامپوننت بررسی شده است؛ این جای آزمایش روی گوشی فیزیکی را نمی‌گیرد.

ساخت production، TypeScript و تست‌های دریچه، بازیابی ورود، نمایش محصول و رسانه با محیط بدون دیتابیس بررسی شده‌اند. ۲۰۹ فایل تصویری محلی نیز کامل decode شدند. عکس‌های آزمایشی و صفحهٔ آزمایش در ZIP نیستند. اتصال دیتابیس، خرید و پرداخت زنده و اجرای اسکریپت‌ها روی ویندوز واقعی در این محیط آزمایش نشده‌اند.

بعد از deploy: هر سه طاق و تصویر پشتشان، ورود به گنجینه‌ها، عناوین بلند، رد کردن/پایان ویدئو و تصاویر را در مرورگر خودتان کنترل کنید.
