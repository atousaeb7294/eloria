# اصلاح گنجینه‌ها، تصاویر و مشخصات محصول

این تغییرات روی کد مخزن آماده شده‌اند؛ اجرای آن‌ها روی کامپیوتر یا سرور، مرحلهٔ جداگانه است.

## تغییرات

- در صفحهٔ خانه، چهار محصول جدیدِ دارای تصویر از هر گنجینه، در قاب‌های کوچک دایره‌ای سمت راست نمایش داده می‌شوند. هر تصویر به محصول خودش پیوند دارد؛ دکمهٔ «گنجینهٔ خرید» زیر تصاویر و نوشتهٔ معرفی سمت چپ قرار دارد. در موبایل، این دو بخش زیر هم هستند. اگر گنجینه کمتر از چهار محصول داشته باشد، فقط محصولات واقعی نمایش داده می‌شوند.
- کارت‌های داخل گنجینه قاب دایره‌ای دارند؛ تصویر با برش مرکزی قاب را پر می‌کند و نام محصول روی لبهٔ پایین قاب قرار می‌گیرد. عکس اصلی کامل همچنان از گالری محصول قابل مشاهده است.
- صفحهٔ محصول و خرید سریع، یک نمایش مشترک «مشخصات محصول» دارند: قیمت محصول، نرخ طلا، وزن و توضیح کوتاه اجزای قیمت. ریز درصدها و مبالغ محاسبات از نمایش خریدار حذف شده‌اند. موتور قیمت‌گذاری تغییری نکرده است.
- متن آثار طلا از «اجرت ساخت طلا» استفاده می‌کند؛ متن آثار نقره و قیمت ثابت متناسب با همان محصول است. اگر مالیاتی در مبلغ نهایی وجود داشته باشد، فقط لحاظ‌شدن آن ذکر می‌شود.
- انتقال صفحه‌ها با React ViewTransition نسخهٔ موجود Next.js هماهنگ شده است. انیمیشن مستقل تغییر پس‌زمینه حذف شده و حالت کاهش حرکت رعایت می‌شود. مکث نشانگر روی منوی خانه دیگر صفحه را بدون کلیک عوض نمی‌کند.
- favicon و آیکون‌های نصب سایت از لوگوی واقعی موجود ساخته شده‌اند. کش نسخهٔ قبلی آیکون‌ها به‌روزرسانی می‌شود.
- گزارش هر اجرای SEO در جدول جداگانه ثبت می‌شود؛ رکوردهای تاریخی روزانه و محدودیت append-only آن‌ها باقی می‌مانند.

## ذخیره‌سازی تصویر روی پارس‌پک

خطای `ENOTFOUND ...supabase.co` مربوط به دسترسی به فضای تصاویر است. برای ذخیرهٔ مستقیم عکس‌های جدید در PostgreSQL، در متغیرهای محیطی پارس‌پک تنظیم کنید:

```dotenv
ELORIA_MEDIA_STORAGE=database
```

حالت پیش‌فرض `auto` است: اگر تنظیمات Supabase کامل باشد ابتدا از آن استفاده می‌شود؛ در خطای شبکه یا پاسخ 5xx عکس معتبر در PostgreSQL ذخیره می‌شود. خطای دسترسی یا نام bucket پنهان نمی‌شود. حالت `supabase` فقط همان فضای خارجی را استفاده می‌کند. حالت `local` فقط برای توسعه است.

عکس‌ها پیش از ذخیره اعتبارسنجی و بازپردازش می‌شوند؛ سقف هر عکس ۸ مگابایت است. عکس‌های ذخیره‌شده در دیتابیس همراه بکاپ دیتابیس نگهداری می‌شوند و حجم دیتابیس را افزایش می‌دهند. در حالت چند نمونهٔ سرور نیز از دیتابیس مشترک خوانده می‌شوند.

**این تغییر عکس‌های قبلیِ موجود در دامنهٔ خراب Supabase را بازیابی نمی‌کند.** برای آن‌ها باید دسترسی فضای قبلی برقرار شود یا اصل عکس‌ها دوباره آپلود شوند. در نبود عکس، نشان برند جای تصویر شکسته نمایش داده می‌شود.

## اعمال فایل تغییرات روی ویندوز

فایل `eloria-treasury-media.patch` را کنار پروژه، مثلاً در `C:\`، قرار دهید. سپس در PowerShell:

```powershell
cd C:\eloria
git status --short
git apply --check C:\eloria-treasury-media.patch
git apply C:\eloria-treasury-media.patch
npm ci
npx prisma generate
npm run typecheck
npm run lint
npm run test:media
npm run test:seo-snapshots
npm run build
```

اگر بررسی `git apply --check` خطا داد، دستور بعدی را اجرا نکنید؛ نسخهٔ محلی با مبنای این تغییرات متفاوت است و باید اختلاف آن بررسی شود. از بازنویسی اجباری فایل‌های محلی استفاده نکنید.

## انتشار

یک migration جدید با نام `20260924010000_product_media_and_seo_runs` وجود دارد. روی محیط هدف، قبل از اجرای نسخهٔ جدید و بعد از تهیهٔ بکاپ دیتابیس اجرا کنید:

```powershell
npm run db:migrate
```

اجرای `npm start` هم طبق تنظیمات موجود پروژه migration را در prestart اجرا می‌کند. اگر از تصویر Docker نهایی استفاده می‌کنید، migration را با هدف migrator/مرحلهٔ release موجود پروژه اجرا کنید؛ runner نهایی ابزار migration ندارد.

پس از انتشار، یک عکس واقعی را در پنل محصول بارگذاری و صفحهٔ محصول و خرید سریع را باز کنید. دسترسی به دیتابیس و پنل زنده در محیط بررسی این تغییرات وجود نداشته است.

## مهارت طراحی

مهارت `vercel-react-view-transitions` از مجموعهٔ رسمی Vercel بررسی و نصب شد. پیاده‌سازی با راهنمای همراه Next.js 16.3.3 تطبیق داده شده است؛ نسخهٔ React یا Next.js ارتقا داده نشده است.

## نتیجهٔ بررسی

- ساخت production، بررسی TypeScript و lint موفق بودند. ساخت با نشانی آزمایشی سایت و بدون اتصال به دیتابیس زنده انجام شد؛ هشدارهای نبود دیتابیس مربوط به همین محیط بررسی هستند.
- آزمون‌های قیمت‌گذاری، ذخیره و خواندن تصویر و ثبت گزارش‌های SEO موفق بودند. آزمون‌های سرویس از داده و اتصال شبیه‌سازی‌شده استفاده می‌کنند.
- migration در PostgreSQL تعبیه‌شده بررسی شد: ذخیرهٔ تصویر، حذف وابسته و جلوگیری از تغییر گزارش‌های تاریخی موفق بودند.
- مرورگر Chromium در اندازه‌های موبایل و دسکتاپ بررسی شد: قاب‌های دایره‌ای، چهار پیش‌نمایش، مشخصات محصول، خرید سریع، انتقال صفحه و عدم تداخل دکمهٔ پشتیبانی؛ خطای اجرایی صفحه مشاهده نشد.
- ارسال شاخه به GitHub به‌علت نبود احراز هویت ممکن نشد. فایل پچ شامل تغییرات کد و آیکون‌هاست؛ روی سایت زنده منتشر نشده است.
