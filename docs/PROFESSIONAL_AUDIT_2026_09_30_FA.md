# بررسی فنی الوریا و چک‌لیست سایت حرفه‌ای

تاریخ: ۳۰ سپتامبر ۲۰۲۶، به وقت تهران
مخزن: https://github.com/atousaeb7294/eloria
نسخه مبنا: `9c1449d136cd20a678fd38c12bda0f121d4a2cdb`

## دامنه و محدودیت بررسی

کد مخزن دریافت شد؛ ساختار صفحات، خرید سریع و قیمت زنده، سبد، مسیر لغو سفارش، تنظیمات آزمون و CI بررسی شدند. مجموعه آزمون‌های موجود برای قیمت، رسانه، امنیت، سئو، حرکت صفحات و کیفیت اجرا شد. این گزارش تأیید بررسی دستی تک‌تک صفحات یا سلامت سایت عملیاتی نیست. دسترسی به دیتابیس عملیاتی، سرویس پیامک، درگاه و نشانی تأییدشده سایت زنده در اختیار نبود. هیچ داده واقعی، سفارش، تنظیم سرور یا نسخه منتشرشده تغییر نکرد.

## اصلاحات انجام‌شده

1. **نمایش اشتباه «فروخته شده» در اولین نمایش خرید سریع:** مقدار اولیه quote برابر null بود و stock به صفر تبدیل می‌شد؛ AddToCartButton آن را محصول فروخته‌شده تفسیر می‌کرد. اکنون پیش از تأیید سرور، متن «در حال بررسی قیمت و موجودی…» و دکمه غیرفعال نمایش داده می‌شود. خطای دریافت نیز پیام مستقل دارد. پیش‌سفارش فقط پس از پاسخ موفق با موجودی صفر نمایش داده می‌شود. قیمت و قابلیت خرید همچنان توسط سرور تعیین می‌شوند.
2. **دکمه افزایش تعداد:** اگر خرید محصول غیرفعال شود، دکمه افزایش تعدادِ کالای موجود در سبد نیز disabled می‌شود؛ پیش‌تر رویداد کلیک عمل نمی‌کرد ولی دکمه ظاهراً فعال بود.
3. **افشای خطای داخلی در لغو سفارش:** مسیر لغو سفارش قبلاً متن هر Error، از جمله خطای دیتابیس، را به مشتری برمی‌گرداند. اکنون فقط خطاهای مشخص کسب‌وکار قابل نمایش‌اند؛ خطاهای غیرمنتظره پاسخ عمومی ۵۰۰ دارند و سمت سرور ثبت می‌شوند.
4. **وابستگی‌ها:** npm audit دو بسته آسیب‌پذیر یافت. در lockfile، `ip-address` از 10.3.1 به 10.7.2 و `undici` از 7.29.0 به 7.30.0 ارتقا یافتند؛ بدون force و بدون ارتقای عمده وابستگی‌های پروژه. اسکن پس از اصلاح صفر آسیب‌پذیری گزارش کرد؛ این نتیجه مربوط به پایگاه اعلام آسیب‌پذیری در زمان اجراست، نه تضمین امنیت مطلق.
5. **تست قدیمی:** تست critical به عبارت حذف‌شده `disabled={!canPurchase}` در صفحه محصول وابسته بود. اکنون اتصال به LivePurchaseBox و شرط تأیید قیمت و قابلیت خرید در محل فعلی بررسی می‌شود.
6. **جلوگیری از بازگشت باگ:** تست رندر اولیه فارسی/انگلیسی اضافه و به CI متصل شد. تست مرورگریِ پاسخ دیررس، خطای API، بازیابی اتصال، موجودی مثبت، منع خرید و موجودی صفر نیز اضافه شد. تست مرورگری در این محیط اجرا نشده است.

## اولویت ادامه کار

- P0: اجرای build و تست‌های دیتابیس/مرورگر روی محیط استاندارد CI؛ سپس بررسی خرید سریع روی موبایل و دسکتاپ.
- P0: در staging، چرخه سفارش تا پرداخت، لغو، بازگشت وجه، رزرو آخرین موجودی و callback تکراری اجرا شود.
- P1: سنجش کارایی، کنتراست، keyboard/screen reader، لینک‌ها و فرم‌های همه صفحات روی دامنه واقعی.

- P2: بهبود تجربه و محتوای محصول بر اساس داده قیف خرید و بازخورد مشتری.

## اعمال و بازبینی تغییرات

تغییرات به GitHub push و روی سایت deploy نشده‌اند. patch همراه شامل کد، lockfile، تست‌ها، CI و همین گزارش است. در checkout تمیز نسخه مبنا ابتدا اجرا کنید:

```bash
git apply --check eloria-audit-fixes.patch
git apply eloria-audit-fixes.patch
npm ci
npx prisma generate
npm run typecheck
npm run lint
npm run test:audit-regressions
npm run audit:dependencies
```

`prisma generate` به تنظیم DIRECT_URL مطابق پروژه نیاز دارد. تست‌های یکپارچه را فقط با دیتابیس تست اجرا کنید. در صورت تغییر مخزن بعد از نسخه مبنا، تعارض patch باید بازبینی شود؛ از اعمال اجباری بدون بررسی استفاده نشود.
