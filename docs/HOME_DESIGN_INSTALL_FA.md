# اصلاح هوم الوریا — نصب و ارسال به گیت

مبنای این بسته، مخزن واقعی `https://github.com/atousaeb7294/eloria` در commit زیر است:

`17e08171f58443a74f3f4bf29f7f19b1f8b3fc61`

مرجع ظاهر، سورس ذخیره‌شدهٔ نسخهٔ سوم طرح آفلاین است. فایل پیوست قبلی در محیط فعلی موجود نبود؛ بنابراین تطبیق بایت‌به‌بایت با آن ممکن نشد. تصاویر پیشنهادیِ ردشده مبنای طراحی نیستند.

## اصلاحات

- پس‌زمینه، لوگوی واقعی، قاب‌های طلایی بیرونی و تیتر نستعلیق دسکتاپ حفظ شده‌اند.
- داخل قاب‌های منتخب‌ها، بستر دایره‌ای با محصول بدون زمینه و حاشیهٔ امن قرار می‌گیرد. `object-fit: contain` نسبت تصویر را حفظ می‌کند. عکس اصلی در نگاه سریع و صفحهٔ محصول کامل نمایش داده می‌شود.
- هوم فقط سه ورودی گنجینه و هشت منتخب دارد؛ بخش تمام آثار و انتخاب رنگ گنجینه روی هوم وجود ندارد.
- ورودی‌ها به صفحات موجود `/{locale}/collections/gold`، `silver` و `weave` وصل‌اند. مسیرها و صفحات قبلی حذف نشده‌اند.
- هشت منتخب، قیمت زنده از API خود فروشگاه، نگاه سریع و لینک جزئیات دارند. مبلغ نمونه وارد کد فروشگاه نشده است.
- صفحهٔ گنجینه و محصول از سطوح شیشه‌ای یاسی/بنفش روشن‌تر و نوشته‌های تیره استفاده می‌کنند؛ پس‌زمینه‌های خودشان حفظ شده‌اند.
- مدیریت جدید `/fa/admin/appearance` امکان انتخاب محصول و عکس هوم، اندازه و ترتیب هشت منتخب را می‌دهد.
- انتخاب عکس هوم، آماده‌سازی خودکار نسخهٔ شفاف را شروع می‌کند. هنگام ذخیره، عکس اصلی هشت منتخب نیز خودکار آماده می‌شود. عکس گالری بازنویسی نمی‌شود؛ خروجی در جدول جدا و با هش عکس کش می‌شود.
- اگر پردازش یا ذخیره خطا بدهد، تنظیمات منتشرشدهٔ قبلی باقی می‌ماند. ذخیره به نشست معتبر مدیر نیاز دارد.
- حرکت هوم شناوری و زاویهٔ محدود همان عکس واقعی است؛ هندسهٔ ۳۶۰ درجه از یک عکس ساخته نمی‌شود. دکمهٔ توقف، تنظیم کاهش حرکت و خروج از دید رعایت می‌شوند.
- چیدمان دسکتاپ چهار ستون و موبایل دو ستون است. آزمون مرورگر برای چهار اندازه آماده شده؛ نتیجهٔ اجرای آن در این محیط تأیید نشده است.

## پیش‌نیاز

Git، **Node.js 22.x** و **Docker Desktop در حالت Linux containers** نصب و Docker روشن باشد. Python داخل کانتینر نصب می‌شود. فایل `.env` سالم سایت خودتان را نگه دارید و با نمونه جایگزین نکنید.

مدل BiRefNet Lite هنگام ساخت image حدود 224 MB دانلود می‌شود؛ کتابخانه‌ها و خود image فضای بیشتری لازم دارند. برای پردازشگر 4 GB حافظه تعریف شده؛ برای Next و سیستم‌عامل نیز حافظهٔ اضافی لازم است. عکس‌ها برای حذف زمینه به API تجاری فرستاده نمی‌شوند. مدل در build و پیش از پردازش عکس دانلود می‌شود. پردازش زمان اجرا داخل شبکهٔ Docker با `internal: true` تعریف شده است؛ opt-out کتابخانه به‌تنهایی مرز شبکه محسوب نمی‌شود. اجرای مستقیم پردازشگر روی میزبان با اینترنت، روش نصب این بسته نیست.

## نصب در پوشهٔ اصلی C:\eloria

برای به‌روزرسانی درجا، بستهٔ جدید `Eloria-C-Update.zip` را بیرون از پروژه استخراج کنید و از داخل آن اجرا کنید:

```powershell
powershell -ExecutionPolicy Bypass -File .\Install-EloriaInPlace.ps1 -RepositoryPath "C:\eloria" -Push
```

این مسیر فقط patch کد را روی مخزن موجود اعمال و commit می‌کند؛ با `-Push` همان commit روی شاخهٔ جدا به گیت می‌رود. فایل‌های `.env*`، آپلودها، داده‌ها و فایل‌های حساس در فهرست تغییر نیستند. فایل‌های هدفِ دارای تغییر ذخیره‌نشده یا فایل‌های ازقبل stage‌شده باعث توقف قبل از جایگزینی می‌شوند. بقیهٔ تغییرات محلی حفظ می‌شوند. از فایل‌های کدی که تغییر می‌کنند در `C:\eloria-update-backups` نسخهٔ پشتیبان گرفته می‌شود. اسکریپت پوشه را پاک یا clone نمی‌کند، npm یا migration اجرا نمی‌کند و main را merge نمی‌کند.

اگر شاخهٔ فعلی commit محلیِ منتشرنشده داشته باشد، ارسال خودکار متوقف می‌شود تا تغییرات دیگری همراه این بسته به گیت نرود. در خطای ورود/شبکه بعد از commit، نام شاخه و دستور تکرار push چاپ می‌شود.

## روش قبلی: ساخت پوشهٔ جدا برای بررسی

دستورهای این بخش فقط مربوط به بستهٔ قدیمی `Eloria-Home-Update.zip` هستند. برای نصب در `C:\eloria` از دستور بالا استفاده کنید.


فایل ZIP را در Downloads ذخیره و این دستورها را اجرا کنید:

```powershell
Expand-Archive "$HOME\Downloads\Eloria-Home-Update.zip" "$HOME\Downloads\Eloria-Home-Update"
Set-Location "$HOME\Downloads\Eloria-Home-Update"
powershell -ExecutionPolicy Bypass -File .\Install-EloriaUpdate.ps1 `
  -RepositoryPath "$HOME\Projects\eloria-home-review" -CodeOnly
```

اسکریپت مخزن را دریافت، شاخهٔ جدا ایجاد و patch را پس از کنترل هش و سازگاری اعمال می‌کند. اگر پوشهٔ مقصد کار ذخیره‌نشده یا commit متفاوت داشته باشد متوقف می‌شود؛ چیزی را حذف نمی‌کند. `ExecutionPolicy Bypass` فقط برای همین اجرای اسکریپت است. پوشهٔ `files` شامل نسخهٔ کامل فایل‌های تغییرکرده برای بازبینی است؛ روش نصب پیشنهادی همان patch کنترل‌شده است.

## ۲. نصب و دیتابیس

`.env` فعلی خودتان را کپی کنید؛ مسیر نمونهٔ زیر را با مسیر واقعی تغییر دهید. برای بررسی از دیتابیس توسعه/staging استفاده کنید.

```powershell
Set-Location "$HOME\Projects\eloria-home-review"
# فقط اگر پوشهٔ جدید هنوز .env ندارد:
Copy-Item "C:\Path\To\Your\Working-Eloria\.env" .\.env
powershell -ExecutionPolicy Bypass -File .\scripts\install-home-design.ps1 -ApplyMigrations
```

اسکریپت Node 22 و Docker را بررسی می‌کند؛ `npm ci`، ساخت پردازشگر، آزمون مصنوعی، Prisma generate، migration، آزمون‌های مستقل، TypeScript و build را اجرا می‌کند و در خطا متوقف می‌شود. تنظیمات پردازش را فقط می‌خواند و بررسی می‌کند؛ هیچ `.env` را ایجاد یا بازنویسی نمی‌کند. `ELORIA_CUTOUT_URL` و توکن پردازش را در متغیرهای محیط فرایند یا تنظیمات میزبان قرار دهید. رمزها چاپ نمی‌شوند.

`-ApplyMigrations` روی دیتابیس مشخص‌شده در `.env` اجرا می‌شود. قبل از اجرا روی دیتابیس اصلی، نسخهٔ پشتیبان معمول خود را تهیه کنید. اسکریپت seed، reset، db push یا force migration ندارد. برای نصب بدون تغییر دیتابیس این گزینه را حذف کنید؛ پیش از استفاده از مدیریت جدید، migration لازم است. گزینهٔ `-SkipBuild` جای تأیید موفقیت build نیست.

## ۳. اجرا و انتخاب محصولات

پنجرهٔ اول:

```powershell
Set-Location "$HOME\Projects\eloria-home-review"
npm run cutout:start
```

پنجرهٔ دوم:

```powershell
Set-Location "$HOME\Projects\eloria-home-review"
npm run dev
```

پردازشگر فقط از `127.0.0.1:8765` در دسترس میزبان است؛ با `Ctrl+C` متوقف می‌شود. برای حذف کانتینر متوقف‌شده: `docker compose -f docker-compose.cutout-local.yml down`.

`http://localhost:3000/fa/admin/appearance` را با حساب مدیریت فعلی باز کنید. محصول و عکس هوم را انتخاب کنید؛ اصل و نسخهٔ شفاف را ببینید، هشت منتخب را مرتب کنید و «آماده‌سازی منتخب‌ها و ذخیرهٔ هوم» را بزنید. پردازش عکس‌ها نوبتی است و بار اول زمان می‌برد؛ دفعه‌های بعد از کش استفاده می‌شود. تا موفقیت همهٔ پردازش‌ها، تنظیمات قبلی هوم باقی می‌ماند.

پیش از اولین ذخیره، تصویر شناور ساختگی نمایش داده نمی‌شود. حداکثر هشت محصولِ قبلاً منتخب‌شده قابل نمایش‌اند؛ برای فعال‌شدن خروجی شفافِ دایره‌ها یک بار مدیریت جدید را ذخیره کنید. غیرفعال/حذف‌کردن یک منتخب آن را از هوم کنار می‌گذارد؛ جایگزین را در مدیریت انتخاب کنید.

حذف زمینهٔ خودکار روی همهٔ عکس‌ها بی‌خطا نیست؛ بند ظریف، زمینهٔ هم‌رنگ یا چند شیء ممکن است به عکس واضح‌تری نیاز داشته باشد. اصل عکس محفوظ است. پیش‌نمایش را با اصل مقایسه کنید؛ برای تغییر عکس اصلی منتخب، از مدیریت خود محصول استفاده کنید.

## ۴. بررسی موبایل و دسکتاپ

بعد از ذخیرهٔ هشت محصول و با بازماندن برنامه:

```powershell
Set-Location "$HOME\Projects\eloria-home-review"
npx playwright install chromium webkit
npm run test:home-browser
npx playwright show-report playwright-report/home-design
```

آزمون شامل دسکتاپ 1440، موبایل Pixel، عرض 320 و تبلت WebKit است. تعداد هشت منتخب، دایره و قاب، بارگذاری عکس، نبود سرریز، لینک گنجینه‌ها، نگاه سریع، Escape و بازگشت فوکوس، کاهش حرکت و حفاظت مدیریت بررسی می‌شوند. عکس‌های گزارش در `test-results/home-design` ذخیره می‌شوند. رنگ‌ها، جزئیات بند و خوانایی متن را هم چشمی بررسی کنید. وضعیت بررسی این محیط در `docs/HOME_DESIGN_QA_FA.md` آمده است.

## ۵. ارسال به GitHub

بعد از بررسی نتیجه:

```powershell
Set-Location "$HOME\Projects\eloria-home-review"
powershell -ExecutionPolicy Bypass -File .\scripts\push-home-design.ps1
```

در نصب درجا، از همان گزینهٔ `-Push` نصاب جدید استفاده کنید. اسکریپت قدیمی زیر فقط فایل‌های فهرست `docs/HOME_DESIGN_FILES.txt` را stage و commit می‌کند و شاخهٔ `eloria/home-refinement-20261021` به مخزن خودتان ارسال می‌شود. `.env` ارسال نمی‌شود؛ force push و merge خودکار main وجود ندارد. ورود GitHub با روش معمول Git خودتان است. اگر main بعد از commit مبنا تغییر کرده، ادغام شاخه را در روند معمول بازبینی کنید.

## ۶. سرویس روی سرور

در نصب Docker فعلی پروژه، توکن پردازش را در تنظیمات واقعی سرور قرار دهید و پورت 8765 را عمومی نکنید:

```powershell
docker compose -f docker-compose.parspack.yml -f docker-compose.cutout.yml build eloria-cutout
docker compose -f docker-compose.parspack.yml -f docker-compose.cutout.yml up -d eloria-cutout eloria
```

ساخت/انتشار image جدید Next و migration مطابق روند موجود سایت جداگانه لازم است؛ دو دستور بالا فقط پردازشگر و اتصال آن را فعال می‌کنند. برای میزبانی صرفاً Node/serverless، میزبان خصوصیِ پردازشگر با محدودیت خروجی اینترنت و مسیر اتصال امن از Next لازم است. آپلود گیت به‌تنهایی این سرویس را نصب نمی‌کند. Docker این محیط در دسترس نبود؛ ساخت و شبکهٔ آن باید روی مقصد بررسی شود.

برای برگشت، نسخهٔ قبلی برنامه را طبق روند انتشار خودتان برگردانید؛ جدول‌های جدید را حذف نکنید. migration، عکس‌ها یا جدول‌های قبلی را بازنویسی نمی‌کند.
