# اصلاح هوم و آماده‌سازی عکس روی سرور

این تغییر برای مخزن `atousaeb7294/eloria` بر پایهٔ نسخهٔ `65b037d` آماده شده است.
انتشار از مسیر GitHub و سپس پارس‌پک انجام می‌شود. فایل‌های env تغییر نمی‌کنند؛
نصب Python یا Docker Desktop و اتصال ویندوز به دیتابیس لازم نیست.

## تغییرات

- حذف زمینه در خود برنامهٔ سرور، در صورت تنظیم‌نبودن سرویس خارجی، انجام می‌شود.
  مدل در زمان ساخت دانلود و با SHA-256 بررسی می‌شود. عکس محصولات به سرویس مدل ارسال نمی‌شود.
- فایل PNG شفاف بدون اجرای مدل پذیرفته می‌شود. عکس اصلی محصول حفظ می‌شود؛
  خروجی برای قاب دایره‌ای آماده می‌شود و حرکت آرام فعلی هوم را دارد.
- در مدیریت هوم، وضعیت پردازش کنار پیش‌نمایش دیده می‌شود. ذخیره تا آماده‌شدن
  عکس غیرفعال است. خطا در آماده‌سازی، عکس منتشرشدهٔ قبلی را عوض نمی‌کند.
- تیترها در موبایل و دسکتاپ از نستعلیق محلی سایت استفاده می‌کنند. متن دکمه‌ها
  فونت خوانا دارد و در قاب باریک، دکمه‌های کارت زیر هم قرار می‌گیرند.
- انتظار عمدی برای انیمیشن ورود به گنجینه و نیاز به کلیک دوم روی عکس برداشته شده است.
  زمان پاسخ شبکه و دیتابیس همچنان روی بارگیری اثر دارد.
- دکمهٔ پخش مجدد ویدیوی ورود پس از ورود به هوم حذف شده است.

## ارسال از ویندوز

ZIP کامل را در یک پوشه استخراج کنید و این دستور را از پوشهٔ استخراج‌شده اجرا کنید:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\publish-home-server-update.ps1 -ProjectRoot 'C:\eloria' -Publish
```

اسکریپت ابتدا مخزن و شاخهٔ `main` و سازگاری تغییرات را بررسی می‌کند، از فایل‌های
درگیر پشتیبان می‌گیرد، فقط فایل‌های همین بسته را commit می‌کند و `main` را push
می‌کند. فایل‌های نامرتبطِ stage‌شده وارد این commit نمی‌شوند. هیچ `npm install`،
مهاجرت دیتابیس یا نصب محلی انجام نمی‌شود. برای اعمال بدون commit/push، گزینهٔ
`-Publish` را حذف کنید.

اگر تغییر محلی ناسازگار یا خطای Git وجود داشته باشد، اسکریپت متوقف می‌شود؛
کد موجود را با reset یا force-push جایگزین نکنید. پیام خطای اصلی را ارسال کنید.
پشتیبان در `C:\eloria-update-backups` نگهداری می‌شود.

## پس از انتشار موفق پارس‌پک

در مدیریت، بخش «چیدمان هوم و دستبند شناور»:

1. محصول و عکس واضح آن را انتخاب کنید؛ آماده‌سازی خودکار شروع می‌شود.
2. برای عکس از قبل انتخاب‌شده، «حذف زمینه و ساخت پیش‌نمایش» را بزنید.
3. پس از ظاهرشدن عکس شفاف، جزئیات بند و سنگ‌ها را بررسی کنید.
4. «۳. ذخیره برای هوم» را بزنید و هوم را تازه کنید.

منتخب‌ها مستقل از محصول اصلی هوم ذخیره می‌شوند. برای تغییر عکس منتخب، عکس اصلی
آن محصول را در مدیریت محصول تغییر دهید و سپس منتخب‌ها را دوباره آماده و ذخیره کنید.

## نیاز سرور و محدودیت بررسی

حذف زمینهٔ عکس معمولی حدود ۲ گیگابایت حافظه برای پردازش می‌خواهد؛ علاوه بر مصرف
خود سایت. برنامه با کمتر از ۲۳۰۴ مگابایت حافظهٔ آزادِ گزارش‌شده پردازش را شروع
نمی‌کند. پلن ۴ گیگابایتی نقطهٔ شروع عملی است، نه تضمین ظرفیت هنگام بار زیاد.
ظرفیت واقعی پارس‌پک شما از این محیط قابل بررسی نبوده و هیچ پلنی تغییر نکرده است.
PNG از قبل شفاف به این میزان حافظه نیاز ندارد.

ساخت سرور باید به Hugging Face و CDN دانلود آن دسترسی داشته باشد. Dockerfile
پروژه برای کتابخانهٔ پردازش به Debian/glibc تغییر کرده است؛ این مربوط به ساخت
روی سرور است و Docker Desktop روی ویندوز لازم نیست. تنظیم معتبر سرویس خارجی
موجود همچنان استفاده می‌شود. جزئیات و مجوز مدل در `services/cutout/NOTICE.md` است.

بررسی‌های انجام‌شده: TypeScript، ESLint فایل‌های تغییرکرده، پردازش عکس واقعی
با فرایند جداگانه، PNG شفاف، حفظ رنگ/حفرهٔ دستبند/بند باریک، آماده‌سازی و ذخیرهٔ
مدیریت با جایگزین آزمایشی دیتابیس، لینک‌های مستقیم، بازیابی ویدیوی ورود و
اعمال امن بسته با حفظ env و تغییرات نامرتبط.

ساخت کامل Next.js در محیط بررسی به خطای داخلی SWC/stacker هنگام خواندن
`next.config.ts` متوقف شد. ساخت نهایی، اجرای متصل به دیتابیس و بررسی ظاهری
موبایل باید پس از انتشار روی سرور تأیید شوند. تأخیر صفر برای شبکه وعده داده نمی‌شود.
