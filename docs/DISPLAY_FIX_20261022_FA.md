# اصلاح نمایش، اینترو و بارگذاری الوریا — ۲۲ اکتبر ۲۰۲۶

مبنای این اصلاح، commit منتشرشدهٔ `4ef47d408ebd1248f4e2b5e6facadfbb771653ba` است.

## تغییرات

- دریافت عکس‌های هوم از تنظیمات اختیاری نمایش جدا شد. نبود جدول تنظیمات یا خطای عکس پردازش‌شده دیگر محصولات موجود را پنهان نمی‌کند. حداکثر هشت محصول عمومی، با اولویت منتخب‌های مدیر، نمایش داده می‌شوند؛ محصول پیش‌نویس نمایش داده نمی‌شود.
- تا وقتی عکس حذف‌زمینه‌شدهٔ مدیر آماده نباشد، عکس اصلی همان محصول در هوم نشان داده می‌شود. فایل خرابِ پردازش‌شده نیز به عکس اصلی برمی‌گردد. این جایگزین، مدل سه‌بعدی یا حذف زمینهٔ انجام‌شده محسوب نمی‌شود.
- نمایش دایره‌ای دو لایه دارد: زمینهٔ برگرفته از همان عکس دایره را پر می‌کند و عکس اصلی بدون تغییر نسبت در بزرگ‌ترین مستطیلِ امن داخل دایره قرار می‌گیرد. عکس افقی و عمودی اندازهٔ یکسانِ اجباری ندارند؛ فایل‌های اصلی تغییر نمی‌کنند.
- فونت «ماندگار» و «از یک گره، تا یک یادگار» در دسکتاپ نستعلیقِ خود سایت است. در موبایل فونت خوانای فارسی و فاصلهٔ مناسب حفظ می‌شود.
- دکمه‌های «ورود به گنجینه‌ها» و «دیدن همهٔ آثار» کنار هم با شیشهٔ بنفش و جزئیات طلایی هستند. دکمهٔ دوم به `/<locale>/products` می‌رود؛ مسیر سه گنجینه همان مسیر قبلی است.
- اینتروی اصلی دو مرحله‌ای به هوم متصل شد. پخش بی‌صدا، پخش دستی هنگام منع autoplay، رد کردن و بازپخش وجود دارد. ورود از لینک‌های داخلی مانند `#hero` اینترو را رد می‌کند؛ بازپخش صریح این حالت را رفع می‌کند.
- ویدیوهای سبک‌تر برای موبایل، تبلت و حالت صرفه‌جویی داده انتخاب می‌شوند. عکس‌های پایین صفحه تنبل بارگذاری می‌شوند، دریافت هشت قیمت تا نزدیک شدن به منتخب‌ها و پایان اینترو عقب می‌افتد و افکت‌های پرهزینهٔ موبایل سبک‌تر شده‌اند. صفحهٔ اصلی پشت درخواست محصولات معطل نمی‌ماند و محتوای آن به‌صورت streaming می‌آید.
- فرم ورود/عضویت کلید عمومی تأیید را از HTML اولیه می‌گیرد، نه یک درخواست اضافی. SDK رسمی بین فرم‌ها مشترک است؛ خطای بارگذاری امکان تلاش مجدد دارد. بررسی واقعی Cloudflare، کلیک کاربر، کنترل انقضا و اعتبارسنجی سمت سرور حفظ شده‌اند. زمان شبکه و پاسخ Cloudflare تضمین‌شدنی نیست.

## نصب روی C:\eloria و ارسال به main

بستهٔ `Eloria-Display-Fix.zip` را بیرون از مخزن استخراج کنید و داخل پوشهٔ استخراج‌شده اجرا کنید:

```powershell
node .\Apply-EloriaDisplayFix.mjs --repository "C:\eloria" --push-main
```

این اجرا ابتدا بررسی می‌کند HEAD محلی با main منتشرشده برابر باشد، فقط فایل‌های بسته را پشتیبان می‌گیرد، patch را بررسی و اعمال می‌کند، یک commit روی شاخهٔ اصلاحات می‌سازد و سپس همان commit را بدون force به main ارسال می‌کند. اگر main حفاظت شده یا هم‌زمان تغییر کرده باشد، مرحلهٔ main متوقف می‌شود. فایل‌های env، داده‌ها، آپلودها، دیتابیس و تغییرات محلیِ نامرتبط وارد commit نمی‌شوند. تغییر محلی روی فایل‌های هدف موجب توقف می‌شود.

بدون `--push-main` فقط اعمال کد و commit محلی انجام می‌شود. خود سایت Node 22.x می‌خواهد؛ اجرای ابزار به‌روزرسانی با Node 24 نیز آزموده شده است. این دستور migration، نصب وابستگی‌ها یا تغییر env انجام نمی‌دهد.

## راه‌اندازی و بررسی

این اصلاح schema یا وابستگی جدیدی اضافه نمی‌کند. قابلیت انتخاب عکسِ حذف‌زمینه‌شده در مدیریت همچنان به migration و سرویس خصوصی حذف زمینهٔ بستهٔ قبلی نیاز دارد. برای رفع خالی بودن هوم، اجرای آن‌ها شرط نیست. اگر سرویس هنوز راه‌اندازی نشده، عکس اصلی نمایش داده می‌شود.

آزمون‌های بدون دسترسی به دیتابیس:

```powershell
Set-Location "C:\eloria"
node --import tsx scripts/test-home-display-fix.ts
node --import tsx scripts/test-intro-recovery.ts
node --import tsx scripts/test-turnstile-display-fix.ts
```

پس از build و راه‌اندازی معمول پروژه، مجموعهٔ مرورگر با حداقل هشت محصول عمومیِ دارای عکس اجرا می‌شود:

```powershell
$env:ELORIA_TEST_BASE_URL = "http://127.0.0.1:3000"
npm run test:home-browser
```

این مجموعه اندازه‌های دسکتاپ ۱۴۴۰، موبایل ۳۹۳، موبایل کوچک ۳۲۰ و تبلت را پوشش می‌دهد و اسکرین‌شات‌ها را در `test-results/home-design` می‌گذارد. متغیر بالا فقط در همان فرایند PowerShell است؛ فایل env را تغییر نمی‌دهد. مرورگر موردنیاز Playwright باید در محیط شما نصب باشد.

## وضعیت تأیید

TypeScript، تحلیل CSS، آزمون‌های دریافت عکس و ترتیب منتخب‌ها، تناسب عکس، کنترل اینترو، بارگذاری و انقضای تأیید امنیتی و رگرسیون‌های امنیتی موفق بودند. SDK و مرورگر در آزمون‌های واحد شبیه‌سازی شده‌اند؛ CAPTCHA واقعی حل نشده است.

سایت فعلی در مرورگر مشاهده شد و خالی بودن عکس‌های هوم و غلبهٔ فونت عمومی روی دو عبارت تأیید شد. علت دقیق خطای دیتابیس سرور بدون لاگ آن تأیید نشده؛ وابستگی شکننده در کد اصلاح شده است.

نسخهٔ تازه هنوز روی دامنه منتشر نشده است. پیش‌نمایش مدیریت‌شدهٔ Sites در محیط تهیهٔ بسته در دسترس نیست؛ بنابراین بررسی دیداری نسخهٔ تازه روی موبایل/دسکتاپ، build نهایی و اندازه‌گیری سرعت واقعی تأیید نشده‌اند. PowerShell ویندوز نیز اینجا در دسترس نیست. نسخهٔ جدید را نباید صرفاً به‌خاطر موفقیت آزمون‌های واحد، از نظر دیداری تأییدشده دانست.
